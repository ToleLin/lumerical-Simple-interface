# 疑難排解:Lumerical FDTD 常見問題與解法

這份清單整理自實際用 Lumerical FDTD(2020 R2)跑了幾百個模擬時踩過的坑。
**標「LumEasy 已自動處理」的不用自己做任何事**;其他的是模擬設定上要注意的地方。

出問題時先看:

- 介面下方「顯示紀錄」(每一步做了什麼、警告、錯誤)
- 存放資料夾裡的 `<檔名>_lumeasy_log.txt`(這次工作的完整紀錄)與 `<檔名>_p0.log`(Lumerical 引擎自己的紀錄)
- 程式本身出錯:`%APPDATA%\LumEasy\crash.log`

> **授權相關的錯誤,一律不要去停止、重啟或修改授權服務 / 授權伺服器。**
> LumEasy 只關掉「自己這次開的」Lumerical,從不碰授權程式;撞到授權錯誤時請等一下再試,或交給管理員處理。

## A. 連線、卡住、當掉

### A1. 開 Lumerical 時卡住不動(沒有錯誤訊息)
- **症狀**:一直停在「開啟 Lumerical…」,CPU 幾乎不動。常見於**當天第一次開**或**午夜前後**(推測是授權檢查 / 換日事件)。
- **LumEasy 已自動處理**:超過「連線逾時」(預設 300 秒)就關掉這次開的 Lumerical,自動重來一次。

### A2. 背景程式意外結束,代碼 -1073741819(0xC0000005)
- **原因 1**:Lumerical 本身是 Qt5 程式,如果繼承到別的 Qt 程式(例如本介面用的 Qt6)的 `QT_*` 環境變數或 DLL 路徑,一開就當掉。
  **LumEasy 已自動處理**:啟動 Lumerical 前清掉所有 Qt 相關環境變數。
- **原因 2**:有些試用 / 網路授權在閒置後會重新啟動,剛好那時開 session 就會崩潰。等一下再按一次即可;不要動授權服務。
- **不要改 `APPDATA` 環境變數**:Lumerical 從那裡讀偏好與授權設定。

### A3. 同一個 Lumerical session 建很多次模型 / 跑很多次,之後卡死
- **原因**:重複使用 session(建模 → 跑 → 清空 → 再建)常在第二輪 `run()` 或 `getresult()` 永遠不返回。
- **LumEasy 已自動處理**:每個工作都開一個全新的 session,做完就關。

### A4. 從含中文的路徑讀寫 .fsp 卡住
- **症狀**:`load("D:/資料/模擬/x.fsp")` 十分鐘以上沒反應,不報錯(傳統硬碟上特別明顯)。
- **LumEasy 已自動處理**:路徑有中文或其他非英數字元時,先在 `%LOCALAPPDATA%\LumEasy\work\` 建模、執行,完成後再複製到你選的資料夾。

### A5. 某些腳本指令會讓 Lumerical 永遠停住
- 不帶參數呼叫 `getmaterial()`、只給名字呼叫 `setmaterial("名稱")` → 永久卡住。**LumEasy 已改用安全寫法**。
- 取監視器的 `farfield` 資料會觸發遠場計算,在背景模式下會停住。**LumEasy 只取 E、H、P、T、index**;要遠場請用 Lumerical 視窗開 .fsp 自己算。
- LSF 腳本的**變數名不能以底線開頭**(`_T = …` 一律 `Failed to evaluate code`)。

### A6. 背景模式下記憶體不足 → 看不到的視窗,run() 永遠不返回
- **症狀 1(開跑前)**:Lumerical 在隱藏模式跳出「Insufficient Memory」對話框,但你看不到,引擎根本沒啟動。
- **症狀 2(跑完收資料時)**:引擎跑到 100% 後印 `This computer does not have sufficient memory`,監視器資料全丟,程式一直等。
- **LumEasy 會提醒**:開跑前粗估記憶體(「模擬區」頁下方),超過可用記憶體 6 成會先問你。
- **解法**:監視器記憶體 ≈ 格點數 × 頻率點 × 分量數 × 16 bytes,通常是大宗 →
  只勾需要的場分量、減少頻率點、大平面監視器用「空間降取樣」2–3、縮小監視器範圍。

### A7. 磁碟滿:最後寫檔時「simulation failed / Unable to write project file」
- 引擎跑完才死,很像記憶體不足。**LumEasy 開跑前會檢查**存放位置的剩餘空間。

### A8. 中斷後 Lumerical 引擎還在背景佔滿 CPU
- 直接殺掉 Python 時,Lumerical 與它的 MPI 引擎會變成孤兒繼續跑。
- **LumEasy 已自動處理**:「停止」會把這次開的整棵行程樹(背景程式 → Lumerical → 引擎)一起關掉,不影響其他程式開的 Lumerical。

## B. 材料

### B1. 材料檔的欄位到底是 (波長, n, k) 還是 (頻率, ε1, ε2)?
- 兩者的數字範圍可能很像(400–700 nm 和 400–750 THz;玻璃的 n ≈ 1.45 和 ε1 ≈ 2.1),**檔名常常騙人**。
- **LumEasy 匯入時**:有欄名就自動判斷;沒有欄名會請你確認,並畫出換算後的 n、k 曲線。
  看曲線是否合理再按「匯入」(玻璃 n ≈ 1.45、k ≈ 0;矽在 500 nm n ≈ 4.2;金屬 ε1 是負的)。上次選的格式會記住。

### B2. 取樣材料要給 ε = (n + ik)²,不是 n + ik
- 「Sampled 3D data」的第二欄是**複數介電常數**。放成 n + ik 不會報錯,但實際得到的是 √n,結果全錯。
- **LumEasy 已自動處理**:一律換算成 ε1 = n² − k²、ε2 = 2nk。

### B3. 虛部的正負號
- Lumerical 用 n + ik、k > 0 代表吸收。有些資料用另一種時間慣例(虛部是負的)。
- **LumEasy 已自動處理**:虛部全部是負的時自動翻正(匯入視窗可以關掉)。

### B4. 模擬波長超出材料資料範圍
- Lumerical 會**自己外插**,數字看起來正常但可能是錯的。**LumEasy 會警告**。

### B5. 內建金屬在可見光的擬合很差
- 例:`Al (Aluminium) - Palik` 預設擬合在 400–750 nm,n 可差到 0.4,鏡面反射率差 3–5%。
- **解法**:「材料」頁 → 新增 → 「複製 Lumerical 內建材料並調整擬合」,擬合容差 0.001、最多係數 12,物件改用新名字。

### B6. 「Sellmeier」材料在 FDTD 裡不色散
- `getindex` 給的是正確的色散曲線,但 FDTD 實際用的是中心頻率的定值。要解析色散請用 Lorentz 模型或匯入取樣資料。

### B7. 內建材料名稱
- 名稱要完全一樣(例如銀沒有 `Ag (Silver) - Palik`,而是 `Ag (Silver) - Palik (0-2um)` / `(1-10um)`;2020 R2 內建庫**沒有 TiO2**)。
- **LumEasy**:「專案」頁按「連線測試」會讀回這台電腦實際的內建材料清單。
- 另外:Lumerical 的 `importmaterialdb` 是**整個材料庫取代**,不是合併。

## C. 結果與分析

### C1. Lumerical 回傳的波長陣列是遞減的
- 內部以頻率遞增存,轉成波長就是 700 → 400 nm。直接丟進 `numpy.interp` **不會報錯但會算錯**。
- **LumEasy 已自動處理**:輸出的頻譜、場圖一律依波長遞增排序。自己寫程式讀 .fsp 時要先 `argsort`。

### C2. getresult 的資料格式
- 向量資料集只有 `"E"`、`"H"`、`"P"`(陣列最後一軸是 x、y、z 分量),沒有 `"Ex"`。
- 數值常是 complex 型別(虛部 0),存 JSON 前要取實部。**LumEasy 已自動處理**。

### C3. 引擎發散,但模擬「看起來」成功
- 場發散時 `run()` 照樣正常結束、監視器也有數字。只有引擎 log(`_p0.log`)會寫 `fields are diverging`,或 Auto Shutoff 衝到 1e4 以上。
- **LumEasy 已自動處理**:每次跑完讀引擎 log,發散時明確警告「結果不可信」。常見原因見 D4–D6。

### C4. 模擬時間跑滿了,能量還沒衰減完
- 頻譜會有截斷造成的漣漪,窄共振附近反射率可能 > 1。**LumEasy 會提醒**。加長模擬時間,或在進階設定加監視器 apodization。

### C5. 穿透率 |T| > 1
- 可能是發散、監視器緊貼光源、或 PML 設定弄壞了功率參考(例如 stabilized PML)。**LumEasy 會提醒**。

### C6. 量反射用的監視器要放在光源「後面」
- 放在光源下游的監視器量到的是淨功率 1 − R,不是 R。「一鍵新增 → 上方」會自動放在光源上方。

### C7. 監視器要圍成封閉盒,不然斜射的光會被算兩次
- 例如側面監視器貫穿全高、上下監視器又蓋過側面時,斜射輻射會先穿過上面、再穿過側面。
- **LumEasy**:「監視器 → 封閉盒(六面)」各面只蓋到盒子為止。

### C8. 分析時的常見假結論
- **收得到的光 ≠ 總出光**:人眼 / 物鏡只收一個角度範圍內的光,總上射功率要乘上收光角的比例。
- **找峰要看連續性**:每個參數點獨立取最大值會跳到別的峰,產生鋸齒狀的假趨勢。
- **比值的分母太小時沒有意義**:分母被數值底噪主導時,選色比之類的比值會亂跳。
- **一次只動一個參數(OFAT)的斜率**不能外插到沒掃過的組合。

## D. 幾何、邊界、光源

### D1. Lumerical 的 2D 只做 x-y 平面
- 一般人畫截面習慣 x-z(z 朝上),但 Lumerical 2D 的模擬平面是 x-y。
- **LumEasy 已自動處理**:你在 2D 畫的是 x-z 截面,程式自動換成 Lumerical 的 x-y;輸出的資料也換回 x-z(座標與場分量都換)。

### D2. 2D 的 TE / TM 命名
- 同一個「電場垂直截面」的模態,3D 叫 TE、Lumerical 2D 叫 TM。
- **LumEasy**:2D 偏振直接選「E 沿 y(TE / s)」或「E 在截面內(TM / p)」,程式換成正確的 Lumerical 偏振角(實測過)。

### D3. 入射角 θ 的正負號(實測,Lumerical 2020 R2)
| 情況 | Lumerical 的 θ > 0 時光往… |
|---|---|
| 3D,z 方向往下注入(Backward) | −x |
| 3D,z 方向往上注入(Forward) | +x |
| 2D,y 方向往下注入 | +x |
| 2D,y 方向往上注入 | −x |

- Lumerical 是把 k 向量繞 z 軸逆時針轉 θ,所以 2D / 3D、上 / 下都不一樣。對稱結構看不出錯,不對稱結構就會反過來。
- **LumEasy 已自動處理**:垂直注入時「θ > 0」一律代表光往 +x 偏。

### D4. 色散材料延伸進 PML → 跑久了發散
- 基板 / 薄膜用的是擬合出來的色散模型,穿過 PML 時,能量降到很低之後會開始指數成長(短模擬看不出來)。
- **解法**:延伸進 PML 的那層改成固定折射率(「材料」頁 → 固定 n,k);或「模擬區 → 進階 → PML 種類」改舊版 UPML 試試。加厚 PML 反而更早爆。

### D5. 很細的網格覆寫觸發發散
- 曾經 5 nm 網格發散、4 nm 和 6 nm 都正常(色散擬合極點 × CPML 的交互)。發散時先換一個網格尺寸試。

### D6. 金屬鏡下方放 PML,p 偏振會慢慢發散
- 鏡子夠厚時,把下邊界改成「金屬」、直接貼在金屬鏡底面(不放基板、不放下方 PML)。

### D7. 對稱邊界 + 模態光源 → 找到假模態
- 2020 R2 在對稱邊界下,模態光源的解算區會被切掉一截,跨在對稱面上的波導找不到真正的導模。**LumEasy 會警告**;要模態光源請用全 PML。

### D8. 物件重疊與挖孔
- Lumerical **沒有布林運算**。重疊的地方由「網格優先順序」決定:數字小的蓋過數字大的(預設 2)。
- 挖孔 = 放一個材料 `etch`(= 背景折射率)、優先順序 1 的同形狀物件。草圖頁的「挖孔」就是這樣做的。

### D9. CAD 匯入的單位
- STL 沒有記錄單位,同一個檔當成 µm 或 mm 會差 1000 倍。**LumEasy**:結構頁會列出用每種單位解讀時的實際尺寸,點一下就換。
- GDSII 自帶單位,不用選。一個 CAD 物件只能有一種材料,不同材料請分檔或分圖層。

### D10. 斜入射的寬頻平面波
- 週期邊界(Bloch)下的寬頻斜入射,其實是「面內 k 固定」,不同波長對應不同角度。要固定角度的寬頻結果請用 BFAST 平面波,或每個角度 / 波長分開跑。

### D11. 繞射級次的編號
- Lumerical `grating` 系列指令的 +m 級,和很多 RCWA 程式(例如 grcwa)的 −m 級是同一個。互相比對時要換號。

## E. 速度

### E1. CPU 行程數
- Lumerical 預設可能只用 1 個行程。行程數太多也不好:背景有程式佔掉一個核心時,MPI 行程會互等,2D 小模型可以慢 20–30 倍。
- 建議:實體核心數 − 1 或 − 2。2D 小模型加行程幾乎沒用,不如多個模擬分開跑。
- 注意:這是 Lumerical 的**全域偏好**,改了會留給之後開的 Lumerical(包含視窗版)。

### E2. 大 3D 模型
- 網格化可能要幾十分鐘,不要用固定的總時限判斷卡死;看引擎 log 有沒有新進度(LumEasy 會把進度顯示在下方狀態列)。
